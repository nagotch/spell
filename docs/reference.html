リファレンス

spell の全機能の一覧です。値と型、演算子、文、prelude が用意する型とメソッド、 ダンダープロトコル、入出力の形を、実装に即してまとめます。 振る舞いの大半は prelude のクラス定義で決まります。迷ったら prelude.sp が正本です。 記号糖衣だけを集めた一覧は糖衣集にあります（各節でも、その機能に属する糖衣はあわせて紹介します）。

整数リテラル

10進数だけです（0x10 のような16進表記はありません）。 そのまま書けるのは、絶対値が 2147483647 以下のリテラルです。 それより大きな値は、リテラル同士の演算で組み立ててください（値は64ビットなので、演算結果は大きくできます）。

bool 値

true / false というリテラルはありません。bool 値は比較や論理演算の結果として得ます （確実に真が欲しいときは 1 == 1、偽は 1 == 0 と書きます）。 表示すると true / false になります。 条件式は bool で書くのが基本ですが、判定は「0でないか」で行われるため、 int（0が偽、それ以外が真）や参照型の値もそのまま条件に使えます。

文字列リテラル

"..." で囲みます。エスケープは \n（改行）、\t（タブ）、\\、\"、\0 だけが特別で、 それ以外の \x は x そのものになります（たとえば \r は復帰コードではなく文字 r です）。 文字列は改行をまたげません。1文字だけの文字リテラルはありません（文字は str の添字が返す int の文字コードで扱います）。

配列リテラル

矢印演算子 <- / ->

オペランドの型で意味が決まります。解決順は次のとおりです。

形1.2.3.
A <- BA.__push_back__(B)A = B.__pop_front__()両辺が int なら比較
A -> BB.__push_front__(A)B = A.__pop_back__()

比較として解決される場合、a <- b は a < -b、a -> b は a > -b と同じです （符号反転される側は1回だけ評価されます）。pop 側の代入先は、通常の代入先と同じ形（変数・添字・フィールド）が使え、新しい変数への束縛もできます。 演算子は通常メソッドを直接呼ばず、ダンダーへだけ展開されます（§12）。 -> はラムダの矢印と字面が重なりますが、左辺の名前が束縛済みなら矢印演算子、未束縛ならラムダの引数名として解決されます（§06）。

03変数・代入・スコープ

変数は代入で生まれます。型は代入した値から推論され、x: int = 5 のように注釈で縛ることもできます。 一度決まった型と違う型の値を代入するとエラーになります。 スコープは関数単位でフラットです（ブロックで区切られません）。 トップレベルでの代入はグローバル変数を作り、関数の中から読み書きできます。 関数の中の代入は、同名のグローバルがあればそのグローバルへ、なければ新しいローカル変数へ行われます。

代入は式であり、値は代入した値です。複数代入 a, b = 値1, 値2 は、値を全部評価してから代入するので、交換がそのまま書けます。 複合代入 x += e は x = x + e と同じですが、代入先が添字の場合は添字式が2回評価されます（副作用のある添字式には注意してください）。

未束縛の名前を読むとエラーにはならず、未初期化の変数として扱われます（値は不定）。 名前の書き間違いが実行時まで残ることがあるので、束縛は代入で明示するのが安全です。

04文とブロック

ブロックの2形式

ブロックは { } 形式と、: ＋インデント形式のどちらでも書け、ブロックごとに独立に選べます（同じファイル・同じ入れ子で混ぜても構いません）。 : 形式では、インデントが戻ったところでブロックが終わります。: の同じ行に文を1つ書く1行形も使えます。 空の : ブロック（文が1つもないもの）はエラーです（{ } の空ブロックは可）。 インデントは空白1つが1列、タブは次の8の倍数の列まで進めて数えます。空行とコメントだけの行は判定に使われません。 どの段にも合わない位置への dedent はエラーになります。 対象は def / class / if / elif / else / while / for と @ 系の糖衣で、ラムダ fn の本体だけは { } のみです。

文の終わりと改行

文は ; で終えますが、; は省略できます。その場合、文の終わりは改行でなければなりません （同じ行に文を続けるには ; が要ります）。ブロック { } の直後はどちらも要りません。余分な ;（空文）は読み飛ばされます。 式の途中での改行は、括弧・角括弧の中では自由です。演算子の直後なら被演算子を次の行に置けますが、行末で式が完結していると、次の行は新しい文として読まれます。 コメントは //（行末まで）と /* */（複数行可、入れ子不可）が使えます。

分岐とループ

文形備考
条件分岐if 式 ブロック、elif、else条件の括弧は任意（if (式) とも書ける）。elif は else の中の if と同じ。文頭の ? でも始められる（? 式 ブロック。if の糖衣、糖衣集参照）
繰り返しwhile 式 ブロック条件の括弧は任意。while に else は無い
反復for 変数 in 式 ブロック、for 式 ブロック（回数）反復プロトコルは §10。else を付けると、break しなかったときだけ else 側が実行される（for...else）
脱出break、continue糖衣として !;（break）と ^;（continue）もある（糖衣集）
復帰return 式式は必須（return; はエラー）

05関数

def 名前(引数, ...) -> 戻り値の型 ブロック で定義します。引数は最大6つです。 引数と戻り値の型注釈は省略でき、戻り値の型は return 文から推論されます。 ただし、推論が済む前の位置（トップレベルの文など）から呼ぶと、戻り値は型不明の値として扱われ、 put のような型の要る操作には直接渡せません。使い回す関数には戻り値の注釈を付けるのが確実です。 再帰も使えます。本体の末尾まで落ちた関数の戻り値は不定です（文として呼ぶだけの関数では問題になりません）。

プログラムはトップレベルに文を並べるだけで書けます。文は上から順に実行されます。 def main() がある場合は、トップレベルの文が先に実行されてから main が呼ばれ、 main の戻り値がプロセスの終了コードになります（末尾まで落ちた場合は 0）。 main が無ければ、トップレベルの文そのものがプログラムで、終了コードは 0 です。

06関数値とラムダ

関数は値として扱えます。関数名をそのまま書くと関数値になり、型は fn(引数の型) -> 戻り値の型 です。 関数値の呼び出しは通常の呼び出しと同じ字面です。メソッドを値として取り出すことはできません（必要な場合はラムダで包みます）。 関数名と同じ名前への代入は、関数ではなく新しい変数の束縛として扱われます。

形意味
fn(x: int) -> int { ... }完全形。引数の型注釈とブロック本体を持ち、戻り値の型も書ける
x -> 式引数1つの糖衣。本体は式1つで、その値が戻り値
(x, y) -> 式引数が複数の糖衣

ラムダが外側のローカル変数を使うと、その変数はラムダ式を評価した時点の値でコピーされて捕捉されます。 コピーはラムダ専用の環境に置かれ、ラムダの中での代入はそのコピーに対して行われて呼び出しをまたいで残りますが、外側の変数とは連動しません。 グローバル変数は捕捉されず、そのまま読み書きされます。 引数の型は、注釈か、代入先・引数位置などの期待型から決まります。どちらからも決まらない場合はエラーになります。 自分自身を代入した変数経由で再帰するクロージャは書けません。 -> の振り分けは §02 の矢印演算子と同じ規則で、左辺の名前が束縛済みなら矢印演算子、未束縛ならラムダの引数名になります。 そのため、束縛済みの変数と同名の引数を持つ裸のラムダ（x -> ...）は書けません（fn 形を使ってください）。

07クラス

class 名前: または class 名前 { } の本体に、フィールド宣言とメソッド定義を並べます。継承はありません。

  • フィールドは 名前: 型 で宣言し、型が必須です。同じ名前のフィールドは二重に宣言できません。フィールドの初期値は書けず、__init__ での代入に集約します
  • メソッドはクラスの中でも def で書き、最初の引数 self が必須です（self の型は所属クラスから決まります）。フィールドへは self.名前 でアクセスします
  • 構築は クラス名(引数, ...) で、__init__ が呼ばれます。__init__ があるクラスでは、正常に終わる全経路で全フィールドが初期化されることが検査され、漏れるとエラーになります
  • __init__ が無いクラスは引数なしで構築でき、フィールドはゼロ値（数値なら 0、参照型なら null 相当）で初期化されます
  • フィールドとメソッドが同名の場合、obj.x はフィールドを読み、obj.x() はメソッドを呼びます。メソッド名への代入はエラーです
  • 関数型のフィールドは obj.m() で、その関数値を呼び出す形になります
  • 演算子や添字はダンダーメソッドで定義します（§12）。__eq__ が無いクラスの == は同一性（同じオブジェクトか）で判定されます
  • __init__ は通常のメソッドとしても呼べます（p.__init__(5) のように再初期化できます）

08ジェネリクス

クラス定義に class Pair<A, B> のように型パラメータを付けられます（最大4つ）。 実装は単相化で、使われた型引数の組み合わせごとに専用のコードが生成されます。 型パラメータは、フィールド・引数・戻り値の型の位置に書けます。

構築時の型引数は、__init__ の引数の値と、代入先の注釈・関数の引数位置・戻り値といった期待型の両方から推論されます。 どちらからも決まらない場合は「型引数を推論できません」というエラーになります。 とくに Dict / Vec / Deque は、ファクトリの引数だけでは型引数が決まらないため、注釈などの期待型が必須です。 型引数は注釈の中に Pair<int, str> と書けます（入れ子も可）。構築式そのものに型引数を書く形はありません。

append は prelude のメソッドではなく、コンパイラが処理する組み込み操作です（メソッドでは呼び出し元の変数を付け替えられないため）。 対象にできるのは、変数・フィールド・配列の要素など、スロットを持つ場所だけです（(a + b).append(x) のような一時値への append はエラー）。 配列は容量を持ち、容量に空きがある間は同じブロックが伸びて別名からも見えますが、 容量を超える append では新しいブロックへコピーして対象の変数だけが付け替わります（別名や、引数として渡した先の呼び出し元には伝わりません）。 作りたての配列は容量＝要素数なので、最初の append は必ず付け替えになります。

10範囲と反復プロトコル

Range

a..b は終端を含まない範囲、a..=b は終端を含む範囲です。値は Range 型で、変数に保持できます。 a > b のときは降順になります（並びの集合は昇順の場合と同じで、順序だけが逆です。たとえば 5..0 は 4, 3, 2, 1, 0）。 rev は向きを反転した範囲を返します。フィールド lo / hi / incl（終端を含むなら 1）も読めます。 Range に __str__ は無いので、そのまま出力はできません。

反復プロトコル

for x in 式 は、式の値の __iter__() が返すイテレータに対して、 __has_next__()（bool を返す）が真の間 __next__() で値を取り出す形に展開されます。 反復対象の式は最初に1回だけ評価されます。ループ変数は最後に反復した値を保持し、反復が0回なら代入自体が起きません。 イテレータが任意メソッド __set_current__(v) を持つ場合、本体でのループ変数への代入は各反復の終わり（と、このループ宛の break / continue の直前）に現在の要素へ書き戻されます。 持たない反復でのループ変数への代入は、書き戻されずに消える事故を防ぐため、コンパイルエラーになります。return で抜ける場合は書き戻されません。

イテレータ対象備考
RangeIterint、Range__set_current__ は無い（ループ変数への代入はエラー）
ArrayIter<T>配列、Vec、Deque配列への反復は配列そのものを見て書き戻しも効く。Vec / Deque は開始時点のスナップショット（to_array()）への反復で、書き戻しもスナップショット側
StrIterstr1文字ずつの str を返す。書き戻しは、代入された文字列の先頭の文字で置き換える（空文字列なら何もしない）
DictIter<K>Dict開始時点のキー並びのスナップショット。__set_current__ は無い

自作クラスも __iter__ / __has_next__ / __next__ を実装すれば for で回せます。 配列への反復中に append した場合、容量内の append は反復にも伸びが見え、 容量を超えて付け替えられた後は、イテレータは元のブロックの範囲をたどります。

11コレクション

Dict<K, V> — 辞書

構築には既定値ファクトリが必須で、d: Dict<str, int> = Dict(zero_int) のように書きます （ファクトリは「無かったキー」を生やすための既定値を作る関数で、キーごとに呼ばれます）。 読み取り d[k] は、キーが無ければファクトリで作った既定値を登録してから返します（defaultdict 式）。 キーに使えるのは __hash__ と __eq__ を持つ型で、等しいキーは等しいハッシュを返す必要があります。 既定のファクトリとして zero_int（0）、zero_bool（偽）、zero_str（空文字列）があり、 それ以外の既定値はラムダで渡します。 Dict 自身に __str__ と __hash__ は無いので、出力したりキーにしたりはできません。

操作内容
d[k]（__getitem__）読み取り。無ければ既定値を生やして返す
d[k] = v（__setitem__）書き込み。上書きしてもキーの挿入位置は変わらない
has(k)キーの有無。d[k] の読み取りで生えたキーも「有り」になる
lenエントリ数
keys()挿入順のキー配列のコピー
__iter__キーの列挙（開始時点のスナップショット）

Vec<T> — 伸びる配列

構築は v: Vec<int> = Vec(zero_int) のように、既定値ファクトリと注釈（などの期待型）が必須です。 末尾への追加は容量の倍増で均し定数時間です。

Deque<T> — 両端キュー

Queue としても Stack としても使える両端キューです。構築は q: Deque<int> = Deque(zero_int) のように、ファクトリと注釈が必須です。 出し入れの実体はダンダー __push_back__ / __push_front__ / __pop_back__ / __pop_front__ で、 公開メソッドはその薄いラッパーです。矢印演算子（§02）でも出し入れできます。 空のときに pop_front / pop_back / front / back を呼ぶのは誤りで、結果は不定です（検査はしません）。

front() / back()先頭 / 末尾を覗く
len要素数

12ダンダープロトコル一覧

演算子や構文は、すべてダンダーメソッドへの書き換えで処理されます。自作クラスが実装できるのは次のとおりです。 シグネチャは、組み込み型が実装する形を基準に示します。

ダンダー使われる場所備考
__init__(self, ...)構築 Cls(...)戻り値の型注釈は書かない。全フィールド初期化の検査対象
__add__ __sub__ __mul__ __div__ __mod__+ - * / %、複合代入、++ / --a += b は a = a.__add__(b)。++ は __add__(1)
__eq__ __ne__== !=、Dict のキー照合__eq__ が無いクラスの == は同一性
__lt__ __le__< <= と連鎖比較> >= は左右を入れ替えて __lt__ / __le__ に帰着。>= の右辺が複合式だと左結合の意味に化ける既知の制限がある
__hash__() -> intDict のキー__eq__ と対で実装する。Dict は __hash__ の無い型をキーにできない
__str__() -> strprint / put、文字列連結での自動変換無ければ出力時にエラー（Range や Dict はこちら）
__getitem__(i) / __setitem__(i, v)a[i] の読み書き、複合代入の対象添字の型は任意（辞書のキーは任意の型）
__iter__() -> イテレータfor x in objイテレータ側は __has_next__() -> bool と __next__() を実装。任意で __set_current__(v)（ループ変数の書き戻し）
__push_back__(v) / __push_front__(v)矢印 q <- v / v -> qどちらか片方だけでもよい（使う側だけ解決される）
__pop_back__() / __pop_front__()矢印 q -> x / x <- q取り出した値を返す形

これ以外に、prelude のクラスが内部で使う __spell_* 始まりの基盤関数がありますが、利用側のコードから直接使うものではありません。 型変換は自動的には行われません（int と str の + はエラーで、x.__str__() と明示します）。 例外として print / put だけは、引数を自動で文字列化します。

13入出力

出力

形内容
print(x)値を文字列化して改行つきで出す。文字列化の規則: 文字列はそのまま、数値は10進、bool は true / false、配列は要素を空白区切り（入れ子も平らに）、クラスは __str__ の結果。__str__ の無い型（Range、Dict など）はエラー
put x, y, ...print の文形。複数の引数を空白区切りで並べて改行まで出す。引数は1つ以上
<< xprint(x) の糖衣（糖衣集）
eprint(x)print と同じ文字列化で、標準エラー出力へ改行つきで出す

入力

in は代入の右辺だけでなく、式の途中でも使えます。

形内容
in整数を1つ読む。負数も読める
in[n]整数を n 個読んで [int] にする
in[h][w]整数を h 行 × w 列読んで [[int]] にする（出力すると平らに並ぶ）
a- = in[n]in[n] の読み取りに - 修飾を付けた形。読んだ各値から 1 を引いて代入する
in_str空白区切りのトークンを1つ読む
in_str[n]トークンを n 個読んで [str] にする
in_line1行をそのまま読む（行末の改行は含まない）
>> a, b, ca = in; b = in; c = in の糖衣。左から順に読む。対象は複数代入の左辺と同じ形が使える。対象は空白区切りでも並べられ、カンマと混在できる（>> a b, c。空白区切りの継続は同じ行の中だけ）
>>> s, ts = in_str; t = in_str の糖衣。空白区切りのトークンを左から順に読む。対象の並べ方は >> と同じ
>> a[n] / >>> s[n]個数形。基底名が未束縛なら、長さ n の配列を作って n 個読む（a = [0] * n のあと各要素へ順に読むのと同じ。>>> 形は [""] * n）。個数式は1回だけ評価される。基底名が束縛済みなら通常の添字形（既存配列の1要素へ1つ読む）。個数形の対象は識別子のみ
yn 式式が真なら Yes、偽なら No を1行出す糖衣

整数の読み取りは、先行する空白を読み飛ばしません。読み取りのたびに区切り文字が1つ消費されるため、 空白1つ（または改行）で区切られた通常の入力では続けて読めますが、先頭に空白がある入力や空白の重なりでは 0 になります。 in_str は先行する空白を読み飛ばし、in_line は行末までをそのまま取ります。

14キーワードと型注釈

キーワード

def class if elif else while for break continue return in in_str in_line put yn fn の16語です。これらは識別子として使えません（変数名・関数名・フィールド名・メソッド名のどれにも使えません）。 in は for x in ... のキーワードと、入力を読む式の両方に使われます。

型注釈を書ける場所

場所形必須かどうか
変数の束縛x: int = 5任意。再代入の型も縛る
関数の引数def f(a: int)任意
関数の戻り値def f() -> int任意（§05 の推論の注意あり）
クラスのフィールドx: int必須
ラムダの引数と戻り値fn(x: int) -> int { ... }任意（期待型からも決まる）
for の反復対象for x in 式: [int] = ...まれなケース用の任意注釈

型名の綴り: int、bool、str、[T]、fn(A) -> B、クラス名（型引数つきは Dict<str, int>）。 注釈は代入のときだけ書けます（再代入に注釈は付けられません）。

15約束事と不定な振る舞い

spell は高速さを優先し、実行時の検査を最小限にしています。次は「言語の約束事」として決まっている挙動です。 うっかり踏むと、エラーではなく不定の結果になります。

事柄約束事
範囲外アクセス配列・文字列・Vec の添字は検査されません。負数や長さ以上の添字の読み書きは不定（多くの場合クラッシュ）
空の Dequepop_front / pop_back / front / back は不定。呼ぶ前に len を確認すること
ゼロ除算未定義（多くの場合クラッシュ）
未束縛の名前の読み取りエラーにならず、未初期化の値（不定）が返る
関数の戻り値return せずに末尾まで落ちた関数の戻り値は不定
整数オーバーフロー2の補数で巻き戻る（エラーにはならない）
引数の上限関数は引数6つまで。超えるとエラー
型引数の上限ジェネリクスの型パラメータは4つまで
入力の形式in は空白を読み飛ばさない（§13）。入力が尽きた後の読み取りは不定
フレーム配列の寿命関数の中で作った配列リテラルをフィールドへ直接代入すると、関数の終了後に宙に浮く。共有したい配列はヒープ側の構築（[fill; n] など）か、引数経由で渡す

コンパイル時のエラーは、日本語のメッセージと位置（行・列と該当箇所の下線）つきで報告され、最初の1件で止まります。 関数やクラスが使われていない場合、そのコードは生成されません（到達可能な関数だけが出力されます）。
