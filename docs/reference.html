リファレンス

spell の全機能の一覧です。値と型、演算子、文、prelude が用意する型とメソッド、 ダンダープロトコル、入出力の形を、実装に即してまとめます。 振る舞いの大半は prelude のクラス定義で決まります。迷ったら prelude.sp が正本です。 記号糖衣だけを集めた一覧は糖衣集にあります（各節でも、その機能に属する糖衣はあわせて紹介します）。

整数リテラル

10進数だけです（0x10 のような16進表記はありません）。 そのまま書けるのは、絶対値が 2147483647 以下のリテラルです。 それより大きな値は、リテラル同士の演算で組み立ててください（値は64ビットなので、演算結果は大きくできます）。

bool 値

リテラルは true / false（短縮形 T / F）で、比較や論理演算の結果としても得ます。 表示すると true / false になります。 条件式（if / while の条件と、! / && / ||（英字形 not / and / or）の被演算子）では、値が真理値として解釈されます。 bool はそのまま、int は 0 が偽でそれ以外が真です。 クラス・配列・文字列の値は、その型に __bool__() -> bool が定義されていればその結果で判定します （str・配列・Vec・Deque・Dict は「長さが 0 でないこと」）。 __bool__ の無いクラスを条件に使うとコンパイルエラーになります。

文字列リテラル

"..." または '...' で囲みます（Python と同じで、どちらの形でも同じ str です）。エスケープは \n（改行）、\t（タブ）、\r（復帰）、\\、\"、\'、\0 と、\xHH（16進2桁で文字コードを直接指定）です。 この表に無いエスケープはコンパイルエラーになります。 文字列は改行をまたげません。文字リテラルという別種のものはなく、'a' も長さ1の str です。 添字 s[i] は1文字の str を返し、文字コード（int）が欲しい場合は s.chars[i] を使います。

f-string

先頭に f を付けると f-string になります（f"..." と f'...' の両形があり、通常の文字列と同じ str です）。 中の {式} が、式の値を文字列化したもので置き換わります。文字列化は print と同じで、__str__ の無い型の値と、型の分からない値は埋め込めません（コンパイルエラー）。 波括弧そのものを書くときは {{ と }} と重ねます。 書式指定（{x:03d} のような : 以降）は未対応で、コンパイルエラーになります。 式の中に文字列リテラルや入れ子の f-string を書けますが、ブロック（ラムダ本体など）とコメントは書けません。

配列リテラル

形意味
[1, 2, 3]要素を並べた配列。要素の型はすべて同じでなければならない（混ぜるとエラー）
[値; 長さ]同じ値で埋めた、実行時に決まる長さの配列。値が配列の場合は、各要素にその複製が入るため、[[-1; w]; h] の行同士は独立で、一行への書き込みが他の行へ伝わることはない（リテラル・変数・呼び出し結果のどれでも同じ。配列の値セマンティクスは §03）

内包表記

[要素式 for 変数 in 対象] は、対象の各要素について要素式を評価して集めた新しい配列です。対象は for 文と同じく反復できるもの（配列・Range・str・Dict のキー・イテレータプロトコルを持つクラス）で、1回だけ評価されます。末尾に if 条件 を付けると条件を満たす要素だけが入り、if は複数並べてもよく（並び順に短絡します）、for 節は1つだけです。糖衣形 [要素式 変数@対象] もあります（糖衣集）。

ループ変数は内包表記の中だけの局所で、外側の同名変数は壊れません。対象の式は外側のスコープで評価され、ループ変数への代入はエラーです。結果はそのまま式として使え、メソッドチェーン・添え字・スライスが付けられます。

03変数・代入・スコープ

変数は代入で生まれます。型は代入した値から推論され、x: int = 5 のように注釈で縛ることもできます。 一度決まった型と違う型の値を代入するとエラーになります。 スコープは関数単位でフラットです（ブロックで区切られません）。 トップレベルでの代入はグローバル変数を作り、関数の中から読み書きできます。 関数の中の代入は、同名のグローバルがあればそのグローバルへ、なければ新しいローカル変数へ行われます。

代入は式であり、値は代入した値です。複数代入 a, b = 値1, 値2 は、値を全部評価してから代入するので、交換がそのまま書けます。 複合代入 x += e は x = x + e と同じですが、代入先が添字の場合は添字式が2回評価されます（副作用のある添字式には注意してください）。

配列は値です。配列型の値は、代入・複数代入の最終束縛・関数の引数と戻り値・配列リテラルの要素・append の引数・添え字代入とフィールド代入の右辺・辞書への格納といった「束縛」のたびにディープコピーされます。 そのため b = a のあとで a を書き換えても b は変わらず、使いまわし（エイリアス）を気にする必要はありません。 対象は配列だけで、クラスインスタンス（str や Dict なども含む）は従来どおり参照として渡ります。メソッドのレシーバ self はコピーされません（sort や append が変数そのものを書き換えるため）。 型の分からない値は深さが決められないためコピーされません。 なお、辞書の値への連鎖代入 d[k][j] = v は読み出した複製への書き込みになり、辞書へは届きません（tmp = d[k] と取り出して書き戻してください）。

どこにも代入されていない名前を読むと、コンパイルエラーになります（定義の判定は文の前後関係ではなく、プログラム全体・関数全体での代入の有無で行います。 そのため、後方で代入されるグローバルを関数から読む前方参照は問題ありません）。 近い名前の変数が1つだけあれば、エラーメッセージに「ヒント: もしかして `名前` ですか（定義は N 行目）」と候補が出ます。

04文とブロック

ブロックの2形式

ブロックは { } 形式と、: ＋インデント形式のどちらでも書け、ブロックごとに独立に選べます（同じファイル・同じ入れ子で混ぜても構いません）。 : 形式では、インデントが戻ったところでブロックが終わります。: の同じ行に文を1つ書く1行形も使えます。 空の : ブロック（文が1つもないもの）はエラーです（{ } の空ブロックは可）。 インデントは空白1つが1列、タブは次の8の倍数の列まで進めて数えます。空行とコメントだけの行は判定に使われません。 どの段にも合わない位置への dedent はエラーになります。 対象は def / class / if / elif / else / while / for と @ 系の糖衣で、ラムダ fn の本体だけは { } のみです。

文の終わりと改行

文は ; で終えますが、; は省略できます。その場合、文の終わりは改行でなければなりません （同じ行に文を続けるには ; が要ります）。ブロック { } の直後はどちらも要りません。余分な ;（空文）は読み飛ばされます。 式の途中での改行は、括弧・角括弧の中では自由です。演算子の直後なら被演算子を次の行に置けますが、行末で式が完結していると、次の行は新しい文として読まれます。 コメントは //（行末まで）と /* */（複数行可、入れ子不可）が使えます。

分岐とループ

文形備考
条件分岐if 式 ブロック、elif、else条件の括弧は任意（if (式) とも書ける）。elif は else の中の if と同じ。文頭の ? でも始められる（? 式 ブロック。if の糖衣）。else / elif は糖衣として | でも書ける（| ブロック が else、| 式 ブロック が elif。for...else の else も同様。いずれも糖衣集参照）
繰り返しwhile 式 ブロック条件の括弧は任意。while に else は無い。文頭の @? 式 ブロック でも書ける（while の糖衣。@ 式 の回数の形と区別するため条件の印 ? を足す。糖衣集参照）
反復for 変数 in 式 ブロック、for 式 ブロック（回数）反復プロトコルは §10。else を付けると、break しなかったときだけ else 側が実行される（for...else）
脱出break、continue糖衣として !;（break）と ^;（continue）もある（糖衣集）
復帰return 式式は必須（return; はエラー）

05関数

def 名前(引数, ...) -> 戻り値の型 ブロック で定義します。引数は最大6つです。 引数と戻り値の型注釈は省略でき、戻り値の型は return 文から推論されます。 ただし、推論が済む前の位置（トップレベルの文など）から呼ぶと、戻り値は型不明の値として扱われ、 put のような型の要る操作には直接渡せません。使い回す関数には戻り値の注釈を付けるのが確実です。 再帰も使えます。本体の末尾まで落ちた関数の戻り値は不定です（文として呼ぶだけの関数では問題になりません）。

プログラムはトップレベルに文を並べるだけで書けます。文は上から順に実行されます。 def main() がある場合は、トップレベルの文が先に実行されてから main が呼ばれ、 main の戻り値がプロセスの終了コードになります（末尾まで落ちた場合は 0）。 main が無ければ、トップレベルの文そのものがプログラムで、終了コードは 0 です。

組み込みの min(a, b, ...) / max(a, b, ...) は可変引数（1個以上、個数の上限なし）で、 引数のうち最も小さい / 大きい値を返します。引数は全て同じ型で、その型の順序（__lt__）で比べます （配列メソッドの min() / max() と同じ意味論）。引数は左から右へ1回ずつ評価されます。 同名のユーザー定義関数があればそちらが優先されます。prelude の abs(x: int) -> int は絶対値を返します （最も小さい int の絶対値は範囲に収まらないため未定義）。

06関数値とラムダ

関数は値として扱えます。関数名をそのまま書くと関数値になり、型は fn(引数の型) -> 戻り値の型 です。 関数値の呼び出しは通常の呼び出しと同じ字面です。メソッドを値として取り出すことはできません（必要な場合はラムダで包みます）。 関数名と同じ名前への代入は、関数ではなく新しい変数の束縛として扱われます。

形意味
fn(x: int) -> int { ... }完全形。引数の型注釈とブロック本体を持ち、戻り値の型も書ける
x -> 式引数1つの糖衣。本体は式1つで、その値が戻り値
(x, y) -> 式引数が複数の糖衣

ラムダが外側のローカル変数を使うと、その変数はラムダ式を評価した時点の値でコピーされて捕捉されます。 コピーはラムダ専用の環境に置かれ、ラムダの中での代入はそのコピーに対して行われて呼び出しをまたいで残りますが、外側の変数とは連動しません。 グローバル変数は捕捉されず、そのまま読み書きされます。 引数の型は、注釈か、代入先・引数位置などの期待型から決まります。どちらからも決まらない場合はエラーになります。 自分自身を代入した変数経由で再帰するクロージャは書けません。 -> の振り分けは §02 の矢印演算子と同じ規則で、左辺の名前が束縛済みなら矢印演算子、未束縛ならラムダの引数名になります。 そのため、束縛済みの変数と同名の引数を持つ裸のラムダ（x -> ...）は書けません（fn 形を使ってください）。

07クラス

class 名前: または class 名前 { } の本体に、フィールド宣言とメソッド定義を並べます。継承はありません。

  • フィールドは 名前: 型 で宣言し、型が必須です。同じ名前のフィールドは二重に宣言できません。フィールドの初期値は書けず、__init__ での代入に集約します
  • メソッドはクラスの中でも def で書き、最初の引数 self が必須です（self の型は所属クラスから決まります）。フィールドへは self.名前 でアクセスします
  • 構築は クラス名(引数, ...) で、__init__ が呼ばれます。__init__ があるクラスでは、正常に終わる全経路で全フィールドが初期化されることが検査され、漏れるとエラーになります
  • __init__ が無いクラスは引数なしで構築でき、フィールドはゼロ値（数値なら 0、参照型なら null 相当）で初期化されます
  • フィールドとメソッドが同名の場合、obj.x はフィールドを読み、obj.x() はメソッドを呼びます。メソッド名への代入はエラーです
  • 関数型のフィールドは obj.m() で、その関数値を呼び出す形になります
  • 演算子や添字はダンダーメソッドで定義します（§12）。__eq__ が無いクラスの == は同一性（同じオブジェクトか）で判定されます
  • __init__ は通常のメソッドとしても呼べます（p.__init__(5) のように再初期化できます）

08ジェネリクス

クラス定義に class Pair<A, B> のように型パラメータを付けられます（最大4つ）。 実装は単相化で、使われた型引数の組み合わせごとに専用のコードが生成されます。 型パラメータは、フィールド・引数・戻り値の型の位置に書けます。

構築時の型引数は、__init__ の引数の値と、代入先の注釈・関数の引数位置・戻り値といった期待型の両方から推論されます。 一般のクラスでは、どちらからも決まらない場合は「型引数を推論できません」というエラーになります。 型引数は注釈の中に Pair<int, str> と書けるほか、構築式そのものにも Pair<int, str>(42, "x") のように書けます（入れ子も可）。 明示した型引数が期待型と矛盾する場合はエラーになります。 とくに Dict は、ファクトリの引数だけでは型引数が決まらないため、注釈などの期待型か、構築時の型引数の明示が必須です。 Vec / Deque はどちらも無ければ要素型が int になるため、注釈なしでも構築できます（§11）。

append は prelude のメソッドではなく、コンパイラが処理する組み込み操作です（メソッドでは呼び出し元の変数を付け替えられないため）。 対象にできるのは、変数・フィールド・配列の要素など、スロットを持つ場所だけです（(a + b).append(x) のような一時値への append はエラー）。 配列は値なので（§03）、append の効果は対象の変数・フィールド・要素そのものにだけ及びます。他の変数が同じ配列を持っていることはなく、引数として渡した先での append も呼び出し元には伝わりません。 内部では容量を持ち、容量を超える append では新しいブロックへ移して対象だけが付け替わります。作りたての配列は容量＝要素数なので、最初の append は必ず付け替えになります。

添え字の回り込み: 通常の添え字 a[i] は、実効添え字を i % a.len（% と同じ Python 式で、負数でも 0 以上）として解釈します。 そのため a[-1] は最後の要素、a[a.len] は先頭の要素、a[a.len + 1] は2番目の要素を指し、読み書きのどちらでも同じです。 入れ子の配列では段ごとに回り込み、座標添え字 a[p] も成分ごとに回り込みます。 長さ 0 の配列は余りが取れないため、添え字アクセスは従来どおり不定です。範囲外を厳密に判定したい場合は安全添え字を使ってください。 str の添え字 s[i] も同じく回り込みます（文字列の節を参照）。

安全添え字 a?[i][j]... は、範囲チェックつきの読み取りです。対象の直後に ? を1回だけ置き、後ろに通常の添え字の連鎖を続けます。 単独で書くと「連鎖の全段とも範囲内（0 <= 添え字 < その段の長さ）か」を表す bool になります。 比較（==, !=, <, <=, >, >=）の直接の被演算子として書くと、どこかの段で範囲外なら比較全体が false（!= でも false）になり、全段範囲内なら要素同士の通常の比較になります。 対象と各添え字はちょうど1回だけ評価され、範囲チェックは浅い段から順に短絡します。対象にできるのは配列と str だけで、Dict や __getitem__ を持つクラスには使えません。 代入先には使えず、連鎖比較の中でも使えません（どちらもコンパイルエラー）。 対象の型が分からない場合（未注釈の引数など）は、範囲チェックを組み立てられないためコンパイルエラーになります（型注釈で型を明示してください）。 添字に Pos2 / Pos3 を渡すこともでき、座標添字と同じ展開を安全化したものになります。要素が str の配列では末尾の文字列も1段と数え、安全形では文字列の長さも範囲チェックに含めます。文字列の段の要素は通常の s[i] と同じです（__getitem__ の戻り型に従います）。

スライス x[i:j] は、配列と str の部分を取り出す読み取り専用の形です（糖衣集にも記載）。 i 以上 j 未満の部分を、要素をコピーした新しい配列／新しい文字列として返し、元の値は変わりません。 端は省略でき（x[i:]、x[:j]、x[:]）、負の添え字は末尾から数え、範囲外の境界は端に丸められます。 j が i 未満なら空になります。ステップ（x[i:j:k]）は無く、代入先にも使えません（どちらもコンパイルエラー）。 安全添え字の中では使えません。

10範囲と反復プロトコル

Range

a..b は終端を含まない範囲、a..=b は終端を含む範囲です。値は Range 型で、変数に保持できます。 a > b のときは降順になります（並びの集合は昇順の場合と同じで、順序だけが逆です。たとえば 5..0 は 4, 3, 2, 1, 0）。 rev は向きを反転した範囲を返します。フィールド lo / hi / incl（終端を含むなら 1）も読めます。 Range に __str__ は無いので、そのまま出力はできません。

反復プロトコル

for x in 式 は、式の値の __iter__() が返すイテレータに対して、 __has_next__()（bool を返す）が真の間 __next__() で値を取り出す形に展開されます。 反復対象の式は最初に1回だけ評価されます。ループ変数は最後に反復した値を保持し、反復が0回なら代入自体が起きません。 イテレータが任意メソッド __set_current__(v) を持つ場合、本体でのループ変数への代入は各反復の終わり（と、このループ宛の break / continue の直前）に現在の要素へ書き戻されます。 持たない反復でのループ変数への代入は、書き戻されずに消える事故を防ぐため、コンパイルエラーになります。return で抜ける場合は書き戻されません。

配列については特例があります。反復対象が変数・フィールド・添え字で辿れる場所にある配列（左辺値）のとき、for はイテレータを介さず元の配列そのものを回ります（借用モード）。 ループ変数への代入は元の配列の現在位置へ書き戻され、要素の束縛も複製ではないため、要素が配列なら row[0] = 9 のような要素経由の書き換えも元の配列へ届きます。 反復は開始時点の配列ブロックを見て長さを読み直すので、容量内の append は反復にも増えますが、容量を超える append で変数が新しいブロックへ付け替わると反復は追随しません。 対象が呼び出し結果・リテラルなどの一時値のときは、この特例は働かず、受け取った時点の複製（スナップショット）を回ります。内包表記も対象外で、要素は複製されて新しい配列に入ります。

イテレータ対象備考
RangeIterint、Range__set_current__ は無い（ループ変数への代入はエラー）
ArrayIter<T>配列、Vec、Deque左辺値の配列への for は借用モードで配列そのものを回り、書き戻しも効く（ArrayIter は一時値の配列にだけ使われる）。Vec / Deque は開始時点のスナップショット（to_array()）への反復で、書き戻しもスナップショット側
StrIterstr1文字ずつの str を返す。書き戻しは、代入された文字列の先頭の文字で置き換える（空文字列なら何もしない）
DictIter<K>Dict開始時点のキー並びのスナップショット。__set_current__ は無い

自作クラスも __iter__ / __has_next__ / __next__ を実装すれば for で回せます。 配列への反復中に append した場合、容量内の append は反復にも伸びが見え、 容量を超えて付け替えられた後は、イテレータは元のブロックの範囲をたどります。

Dict<K, V> — 辞書

構築には既定値ファクトリが必須で、d: Dict<str, int> = Dict(zero_int) のように書きます （ファクトリは「無かったキー」を生やすための既定値を作る関数で、キーごとに呼ばれます）。 型引数を構築に明示すれば、注釈なしでも d = Dict<str, int>(zero_int) と書けます。 ファクトリの値は読み取りで観測できるため、Vec / Deque のような引数なし構築はありません。 読み取り d[k] は、キーが無ければファクトリで作った既定値を登録してから返します（defaultdict 式）。 キーに使えるのは __hash__ と __eq__ を持つ型で、等しいキーは等しいハッシュを返す必要があります。 既定のファクトリとして zero_int（0）、zero_bool（偽）、zero_str（空文字列）があり、 それ以外の既定値はラムダで渡します。 Dict 自身に __str__ と __hash__ は無いので、出力したりキーにしたりはできません。

Pos2 / Pos3 — 座標

グリッド上の座標を表すクラスです。Pos2 はフィールド x: int、y: int、Pos3 はそれに z: int を加えたものを持ちます。 式の位置で (1, 2) と書くと Pos2、(1, 2, 3) と書くと Pos3 のリテラルになります（糖衣集の「式の糖衣」参照）。 要素ごとの + / -、int とのスカラー倍 *、等価性 == / !=、辞書順の < / <=（x、次に y、次に z の順で比較）、添字 p[0]（x が 0）を備え、 __hash__ があるため Dict のキーにできます。文字列化は空白区切り（"1 2" / "1 2 3"）です。 添字の範囲外は他の添字アクセスと同じく検査されません。 入れ子配列への添字としても使えます（a[p] は a[p[0]][p[1]] と同じ。糖衣集の「式の糖衣」参照）。 ゼロ値は zero_pos2() / zero_pos3() で、Deque<Pos2>() のような引数なし構築の埋め草にも自動で使われます。

>> a, b, ca = in; b = in; c = in の糖衣。左から順に読む。対象は複数代入の左辺と同じ形が使える。対象は空白区切りでも並べられ、カンマと混在できる（>> a b, c。空白区切りの継続は同じ行の中だけ）
>>> s, ts = in_str; t = in_str の糖衣。空白区切りのトークンを左から順に読む。対象の並べ方は >> と同じ
>> a[n][m]... / >>> s[n][m]...個数形。基底名が未束縛なら、角括弧の並びを全て個数として、入れ子配列を作って全要素を行順に読む（一次元は a = [0] * n のあと各要素へ順に読むのと同じ。>>> 形は [""] * n）。角括弧を重ねれば n 次元になる（直方体のみ）。個数式はそれぞれ1回だけ評価される。小配列は枠ごとに作られ、行同士で共有されない。いずれかの個数が 0 ならその方向は空になる。基底名が束縛済みなら通常の添字形（既存配列の1要素へ1つ読む）。個数形の対象は識別子のみ
yn 式式が真なら Yes、偽なら No を1行出す糖衣

整数の読み取りは、先行する空白を読み飛ばしません。読み取りのたびに区切り文字が1つ消費されるため、 空白1つ（または改行）で区切られた通常の入力では続けて読めますが、先頭に空白がある入力や空白の重なりでは 0 になります。 in_str は先行する空白を読み飛ばし、in_line は行末までをそのまま取ります。

14キーワードと型注釈

キーワード

def class if elif else while for break continue return in in_str in_line put yn fn の16語です。これらは識別子として使えません（変数名・関数名・フィールド名・メソッド名のどれにも使えません）。 in は for x in ... のキーワードと、入力を読む式の両方に使われます。

型注釈を書ける場所

場所形必須かどうか
変数の束縛x: int = 5任意。再代入の型も縛る
関数の引数def f(a: int)任意
関数の戻り値def f() -> int任意（§05 の推論の注意あり）
クラスのフィールドx: int必須
ラムダの引数と戻り値fn(x: int) -> int { ... }任意（期待型からも決まる）
for の反復対象for x in 式: [int] = ...まれなケース用の任意注釈

型名の綴り: int、bool、str、[T]、fn(A) -> B、クラス名（型引数つきは Dict<str, int>）。 注釈は代入のときだけ書けます（再代入に注釈は付けられません）。

15約束事と不定な振る舞い

spell は高速さを優先し、実行時の検査を最小限にしています。次は「言語の約束事」として決まっている挙動です。 うっかり踏むと、エラーではなく不定の結果になります。

事柄約束事
範囲外アクセス配列・文字列・Vec の添字は検査されません。負数や長さ以上の添字の読み書きは不定（多くの場合クラッシュ）
空の Dequepop_front / pop_back / front / back は不定。呼ぶ前に len を確認すること
ゼロ除算未定義（多くの場合クラッシュ）
未束縛の名前の読み取りエラーにならず、未初期化の値（不定）が返る
関数の戻り値return せずに末尾まで落ちた関数の戻り値は不定
整数オーバーフロー2の補数で巻き戻る（エラーにはならない）
引数の上限関数は引数6つまで。超えるとエラー
型引数の上限ジェネリクスの型パラメータは4つまで
入力の形式in は空白を読み飛ばさない（§13）。入力が尽きた後の読み取りは不定
フレーム配列の寿命配列リテラルはヒープに作られ、フィールドへの代入でも複製されるため、関数の終了後に宙に浮くことはない

コンパイル時のエラーは、日本語のメッセージと位置（行・列と該当箇所の下線）つきで報告され、最初の1件で止まります。 関数やクラスが使われていない場合、そのコードは生成されません（到達可能な関数だけが出力されます）。
