自作プログラミング言語

spell

spell は、競技プログラミングのために作っている小さなコンパイル言語です。 Python に似た読みやすい基本構文に、頻出する処理を一文字で書ける記号糖衣を重ね、 C で書かれたコンパイラが x86-64 のアセンブリへ直接コンパイルします。 インタプリタではありません。実行ファイルになるので、スクリプト言語より速く動きます。

コンパイラ

x86-64 アセンブリ

01最初のプログラム

<< は「式を評価して1行で出す」出力の糖衣です。 プログラムはトップレベルに文を並べるだけで書けます。main 関数は要りません。

ビルドは2段です。コンパイラがアセンブリを出し、小さな C のランタイムと一緒にリンクします。

spell -S -o hello hello.sp   # hello.s ができる
cc -o hello hello.s tests/funcs.c
./hello

コンパイラ自体のビルドは make -C src です（spell と言語サーバー spell-lsp ができます）。 Nix ではリポジトリの flake がパッケージを用意しているので、nix build でも同じものが得られます。

02どんな言語か

意味論は Python 式

迷うところは Python に寄せてあります。除算は床除算で、-7 / 2 は -4、 -7 % 2 は 1 です。比較は 0 < x < 10 と連鎖でき、 for には else が付き、反復はイテレータプロトコルで統一されています。

記号糖衣は、必ず正規形を持つ

入力は >> x;、出力は << x;、繰り返しは i@n { } のように短く書けます。 ただし糖衣は見た目の遊びではなく、すべて通常の構文へ一意に展開できるものだけを採用しています。 頻度が低い記号は、慣れが効かないので入れません。

コンパイラは最小限、豊かさはライブラリで

配列・文字列・辞書の振る舞いは、コンパイラの特殊扱いではなく、起動時に読み込まれる prelude のクラス定義として書かれています。添字や演算子は __getitem__ や __add__ のようなダンダーメソッドへの展開で統一され、 利用者定義のクラスも同じ規約で演算子を持てます。ジェネリクスは単相化で、 Dict<str, int> のような型ごとに専用のコードを生成します。

エラーは日本語で、場所を示す

型エラーや構文エラーは、ファイル名・行・列と、問題の範囲への下線つきで報告されます。 最初のエラーで止まるので、直す順番に迷いません。

速さについて

参考値として、作者の環境（2026年11月）での単純なベンチマークでは、ループ加算・再帰・配列走査で CPython のおよそ2倍から18倍の速度でした。ネイティブコードになる以上、桁はスクリプト言語と変わります。 最適化はまだ最小限で、C の最適化なし（-O0）と比べて数倍の差があります。

03目次

A 言語ツアー 文・型・分岐とループから、クラス、ジェネリクス、クロージャ、辞書、入出力まで。例はすべて実行確認済みです。 B リファレンス 全機能の一覧。値と型、演算子、組み込み型とメソッド、ダンダープロトコル、入出力の形を引くためのページです。 C 糖衣集 糖衣構文だけを集めた一覧。各糖衣について、記号形とそれが書き換わる正規形を対応させます。 D エディタ連携 言語サーバー spell-lsp と NeoVim の設定。診断が編集のたびに返ります。 E 設計メモ 言語設計の決定事項とその理由の記録です。仕様の背景を知りたいときに。
