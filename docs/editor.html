エディタ連携

言語サーバー spell-lsp が、コンパイラの診断をエディタへ返します。 現在の対応範囲は診断だけです。補完・ホバー・定義ジャンプはまだありません。

01spell-lsp

spell-lsp はコンパイラと一緒にビルドされる言語サーバーです。 ファイルを開く・編集するたびに全文をチェックし、構文エラーと型エラーをすべて publishDiagnostics で返します（上限50件）。 位置情報のあるエラーは該当箇所に、無いものはファイルの先頭に出ます。 チェックは変更のたびに子プロセスで実行されます（コンパイラの状態を持ち越さないため）。

配置で大事なのは1点だけです。spell-lsp は prelude.sp を 実行ファイルと同じフォルダから探すので、2つを並べて PATH の通った場所へ置いてください。 

make -C src                       # spell と spell-lsp ができる
cp src/spell-lsp src/prelude.sp ~/.local/bin/

02NeoVim の設定

リポジトリの tools/neovim/ に、ファイルタイプ検出とシンタックスハイライト、 サーバー起動のスニペットが入っています。起動スニペットの中身はこれだけです。 この中身を init.lua 等へ貼って使います。

*.sp は NeoVim 本体が回路シミュレーションの Spice 用に使っている拡張子と重なるため、 spell 側の検出は上書きで登録しています（tools/neovim/ftdetect/spell.vim）。 シンタックスハイライトは tools/neovim/syntax/spell.vim にあります。

03制限事項

  • 診断は最大50件までです。
  • ドキュメント同期は全文送信（Full）です。
  • 位置の列は文字（コードポイント）単位で返します。日本語を含む BMP の文字では LSP 標準の UTF-16 単位と一致しますが、BMP 外の文字がエラー位置より前にある行では、列がずれることがあります。

サーバーの動作確認には python3 tools/neovim/lsp_smoke.py が使えます。 起動して JSON-RPC を流し、正常系・型エラー・構文エラー・修正で診断が消えること・終了処理を確認します。
